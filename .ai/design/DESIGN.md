# DeepCore DESIGN.md

# DeepCore Design Constitution

## Product Identity

DeepCore is not an AI application.

DeepCore is a calm cognitive operating system that helps people understand, connect, and revisit their own knowledge.

The product should always feel trustworthy, timeless, quiet, and deeply personal.

Users should feel like they are entering their own thinking environment—not interacting with an AI chatbot or enterprise dashboard.

---

# Product Platforms

DeepCore is designed as a platform ecosystem.

Primary platform:
- Desktop Web Application

Future platforms:
- iPad
- iPhone

Every interface should be designed so it naturally adapts across these platforms.

Never create interactions that only work on desktop.

Desktop-first.
Mobile-ready.

---

# Design Philosophy

DeepCore values:

- Calm over stimulation
- Clarity over density
- Understanding over analytics
- Thinking over productivity
- Trust over excitement
- Context over navigation

The interface should reduce mental effort rather than impress visually.

---

# Emotional Goals

Every screen should make users feel:

• Oriented

• Calm

• In control

• Curious

• Confident

Never overwhelmed.

Never rushed.

Never distracted.

---

# Visual Language

The interface should feel:

Editorial.

Minimal.

Quiet.

Sophisticated.

Purposeful.

Professional.

Timeless.

Avoid visual trends that will age quickly.

Typography should establish hierarchy more than colored containers.

Whitespace is a design tool.

---

# Avoid

Never generate:

- AI dashboards
- ChatGPT-style interfaces
- Analytics dashboards
- Enterprise SaaS layouts
- Cyberpunk aesthetics
- Excessive gradients
- Glassmorphism overload
- Floating neon effects
- Decorative visual noise
- Oversized hero banners
- Gamification
- KPI-first layouts

DeepCore is a thinking environment.

Not an AI product.

---

# Information Hierarchy

Every screen should answer one primary cognitive question.

Information should appear in this order:

1. Recognition
2. Orientation
3. Understanding
4. Action

Never ask users to act before they understand.

---

# Navigation Philosophy

Navigation should feel natural.

Prefer:

Context

↓

Relationship

↓

Meaning

Avoid:

Folders

↓

Hierarchy

↓

Configuration

The product should encourage exploration rather than browsing.

---

# Interaction Principles

Every interaction should:

Explain first.

Reveal second.

Configure last.

Progressive disclosure should be used throughout the application.

Advanced functionality should appear only when needed.

---

# Trust

Trust is a primary feature.

Always communicate:

- what DeepCore knows
- what it ignores
- what it stores
- where data lives
- why permissions are requested

Never hide data access.

Never surprise users.

Privacy should feel visible.

---

# Components

Components should be reusable.

Prefer flexible layouts over screen-specific widgets.

Avoid building one-off visual components.

The design system should scale naturally across desktop, tablet, and mobile.

---

# Motion

Motion should be subtle.

Animations should communicate:

- continuity
- hierarchy
- focus

Never decoration.

---

# Accessibility

Readable typography.

Comfortable spacing.

Clear interaction targets.

Keyboard-first.

Touch-friendly.

High contrast.

Responsive layouts.

---

# Design Inspirations

Inspired by:

- Apple Human Interface Guidelines
- Arc Browser
- Linear
- Raycast
- Obsidian
- Notion typography
- Apple System Settings

Do not imitate any single product.

DeepCore must develop its own visual identity.

---

# Connector Experience

Connecting knowledge sources should feel like onboarding a trusted collaborator.

The experience should progressively guide users through:

Discover

↓

Understand

↓

Trust

↓

Configure

↓

Preview

↓

Synchronize

↓

Verify

↓

Manage

Never expose unnecessary technical details early.

---

# Home Experience

Home is not a dashboard.

Home is orientation.

It should answer:

Where was I?

What changed?

What deserves attention?

What should I continue?

---

# Assistant Experience

The Assistant is not the product.

The Assistant is one way of interacting with the product.

Conversations always begin with context.

Responses always provide evidence.

The Assistant should feel like a collaborative thinking partner rather than an answering machine.

---

# Overall Principle

Design for calm cognition.

Every decision should help users think more clearly.

If a design element does not improve understanding, remove it.
