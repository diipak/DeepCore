# Information Architecture Specification
## DeepCore Product Foundation

---

### 1. Information Philosophy

In DeepCore, information is not treated as a static commodity to be indexed and hoarded. It is treated as an active component of human thought. The design of information organization is guided by three core philosophies:

*   **Attention is the Finite Resource**: The human capacity for focus is limited and easily fractured. The primary function of the Information Architecture is not to maximize data density, but to protect, preserve, and focus the user's attention.
*   **Information Exists to Support Thinking**: An artifact (a note, a transcript, a document) has cognitive utility only in relation to what the user is currently reasoning about. Information is presented to establish context, reduce recall effort, and spark correlation—never to fill visual space.
*   **Relevance Over Retrieval**: Locating a specific document is a low-level utility. The system's value lies in highlighting *relevance*—exposing how the active thought relates to the broader web of the user's understanding.

---

### 2. The Attention Model

To maintain cognitive flow, information is organized into five concentric layers of attention. This model dictates how information is prioritized and displayed on any screen or viewport within DeepCore:

```
                  ┌───────────────────────────────┐
                  │       Dormant Knowledge       │
                  │  ┌─────────────────────────┐  │
                  │  │  Background Awareness   │  │
                  │  │  ┌───────────────────┐  │  │
                  │  │  │Supporting Context │  │  │
                  │  │  │  ┌─────────────┐  │  │  │
                  │  │  │  │Current Focus│  │  │  │
                  │  │  │  │  ┌───────┐  │  │  │  │
                  │  │  │  │  │ Immed │  │  │  │  │
                  │  │  │  │  └───────┘  │  │  │  │
                  │  │  │  └─────────────┘  │  │  │
                  │  │  └───────────────────┘  │  │
                  │  └─────────────────────────┘  │
                  └───────────────────────────────┘
```

1.  **Immediate Attention (The Focal Point)**: The exact line of text being drafted, the specific question being asked, or the exact document currently being read. This layer requires maximum focus and zero visual distraction.
2.  **Current Focus (The Active Workspace)**: The broader project, document list, or active thread that directly surrounds the focal point. This includes the primary document's contents and immediate work-in-progress materials.
3.  **Supporting Context (The Local Associations)**: Readily accessible, related concepts, direct references, and adjacent notes that are directly linked to the current focus (e.g., linked research notes, mentioned people, or related transactions).
4.  **Background Awareness (The Peripheral Signals)**: Quiet, system-surfaced observations that hover at the edge of attention (e.g., a note that has become dormant, a broken link, or a newly discovered concept overlap). These are visible but never disruptive.
5.  **Dormant Knowledge (The Vault)**: The vast repository of the user's accumulated understanding that is not currently related to the active thread. It remains completely silent and out of sight until explicitly recalled by a search, a query, or a semantic association.

---

### 3. Information Priority Model

When multiple pieces of information compete for space or attention, priority is resolved deterministically using the following hierarchy:

| Priority | Layer | Description | Example |
| :--- | :--- | :--- | :--- |
| **1 (Highest)** | **User Intent** | Information explicitly requested by the user's active search, query, or selection. | Active search results, direct answers. |
| **2** | **Active Focus Context** | Primary content and explicit user-declared relationships of the active item. | The body of the open note, direct WikiLinks. |
| **3** | **Emergent Connections** | Implicit relationships and concepts discovered by the intelligence engine. | Semantic concept matches, shared tags. |
| **4** | **System Observations** | Temporal patterns and structural notifications generated by background signal analysis. | Dormancy alerts, orphan notes, broken links. |
| **5 (Lowest)** | **Static Metadata** | System timestamps, file details, and technical identifiers. | Ingested date, file paths, system stats. |

### 4. Experience Spaces

Rather than designing around traditional app pages, DeepCore is organized into four conceptual **Experience Spaces**. Screens and interfaces are merely portals into these spaces:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           Awareness Space                               │
│  (The Cognitive Home: active focus, recent activity, observations)       │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
            ┌────────────────────────┴────────────────────────┐
            ▼                                                 ▼
┌────────────────────────┐                        ┌───────────────────────┐
│    Knowledge Space     │                        │  Understanding Space  │
│  (Vault of Artifacts:  │◄──────────────────────►│ (Semantic Web: Themes,│
│  notes, files, videos) │                        │  Graph, Proximity)    │
└────────────────────────┘                        └───────────────────────┘
                                     │
                                     ▼
                        ┌─────────────────────────┐
                        │  Administration Space   │
                        │ (Control Room: sync,    │
                        │  health, config)        │
                        └─────────────────────────┘
```

#### Awareness Space
*   **Purpose**: To orient the user and reflect their current mental state.
*   **Primary Responsibility**: Exposing active context, recent reflections, and peripheral observations.
*   **Interface Representation**: *Home Screen*.

#### Knowledge Space
*   **Purpose**: To serve as the durable repository of recorded facts and experiences.
*   **Primary Responsibility**: Providing detailed inspection, search, and reading layouts for individual artifacts.
*   **Interface Representation**: *Memories List, Document Viewer, Detail Inspections*.

#### Understanding Space
*   **Purpose**: To expose the semantic connections and conceptual structure of the user's second brain.
*   **Primary Responsibility**: Visualizing organic concept relationships, browsing conceptual hubs, and mapping proximity.
*   **Interface Representation**: *Themes List, Connection Maps, Graph Explorer*.

#### Administration Space
*   **Purpose**: To manage the health, configuration, and structural integrity of the system.
*   **Primary Responsibility**: Displaying system diagnostics, managing sync runs, configuring providers, and running database migrations.
*   **Interface Representation**: *Platform Center, System Diagnostics, Ingestion Logs*.

### 5. Cognitive Information Hierarchy

Within any experience space or component, information must be structured in descending order of cognitive abstraction:

1.  **Attention Layer**: The immediate, high-level summary or text that requires active processing (e.g., the title of a document, the direct response from the assistant).
2.  **Understanding Layer**: Semantic abstractions that explain context and relationships (e.g., related themes, why a link exists, how an observation was triggered).
3.  **Evidence Layer**: The raw segments of text, quotes, or timestamps that prove the relationship or observation (e.g., matching text snippets, content hashes, matching tags).
4.  **Metadata Layer**: Descriptive data about the origin of the information (e.g., file paths, source system, file sizes, last modified dates).
5.  **Implementation Layer**: Low-level details of system execution (e.g., database IDs, content index versions, background run identifiers). This layer is hidden from the primary user interface and exposed only to developer diagnostics.

---

### 6. Context Architecture

Context is the active subset of the registry that is currently loaded into the intelligence engine. Context exists in four states:

*   **Active Context**: Derived dynamically from trusted attention signals (such as the document currently being viewed, the workspace folder currently in focus, or the active conversation thread). This context dictates what memories and concepts are primed in the Assistant's retrieval window.
*   **Transient Context**: Short-lived, session-specific context (such as active search queries, temporary filters, or single-turn assistant questions). It expires immediately when the user clears a search, changes views, or shifts focus.
*   **Persistent Context**: Context that survives application restarts (such as user-declared project associations, pinned items, custom cognitive threads, and approved/ignored concept overrides).
*   **Dormant Context**: Historically relevant context that has fallen out of active use (e.g., notes and files associated with projects that have not been modified for 30+ days). It is omitted from active workspace packaging but remains indexed and discoverable via search or direct query.

---

### 7. Navigation Philosophy (Purpose-Driven Navigation)

Navigation in DeepCore must align with the user's intent. Instead of mechanical pathways (nested directories, tab lists), navigation is classified by four purposes:

*   **Navigating to What the User is Doing**: Returning to active tasks, resuming recent focus, or responding to background observations. The system supports this by placing the most recent cognitive focus and active observations at the center of the Awareness Space.
*   **Navigating to What the User Knows**: Directly retrieving specific artifacts or topics. The system supports this through a global, command-driven search interface that allows instant jumping to any item, bypassing structural hierarchies.
*   **Navigating to What the User is Exploring**: Discovering related ideas and mapping connections. The system supports this via *proximity navigation*—clicking on concept chips, related items, or connections within an active artifact to morph the workspace around the new focal point.
*   **Navigating to How the Platform Works**: Adjusting parameters, checking health, or initiating synchronization. The system supports this by isolating these operations inside a dedicated administrative portal, ensuring they never bleed into the cognitive spaces.

---

### 8. Platform Isolation

To maintain a calm, distraction-free environment, a strict boundary is enforced between cognitive workspaces and administrative controls:

*   **No Bleeding of Infrastructure Status**: Database health, sync run performance metrics, provider versions, and ingestion errors must remain completely invisible within the Awareness, Knowledge, and Understanding spaces.
*   **Dedicated Portal Access**: The *Platform Center* is the exclusive interface for administrative control. It requires intentional navigation to enter.
*   **Cognitive Calm Invariant**: Synchronization processes silently in the background. The user is only notified of sync status via a passive indicator on the Home screen (e.g., "Private Memory Active"). If a sync failure occurs, it does not interrupt active work; the error details are quietly recorded in the Administration Space for later review.
